# Proposed SeqSero2 v1.4.0 issue replies

These are draft replies for all 50 issues reviewed. v1.4.0 is prepared locally, not yet published. No replies have been posted and no issue statuses have been changed. For a prepared fix, closure is recommended only after release/deployment verification. Historical closed issues remain closed without assuming their original biological results were reproduced.

## #1 — Duplicate sequence error

[GitHub issue](https://github.com/denglab/SeqSero2/issues/1) · Recommended status: **Keep closed**

> The original alpha-version dataset was not available for reproduction. The prepared v1.4.0 changes make failed assembly/BLAST commands return a failure instead of silently producing an antigen-negative prediction. This does not establish the original cause of the duplicate-sequence error.

## #2 — os.system calls to other modules

[GitHub issue](https://github.com/denglab/SeqSero2/issues/2) · Recommended status: **Keep closed**

> The prepared v1.4.0 patch replaces the remaining shell-built commands with subprocess argument lists and Python filesystem operations. Helpers can be imported without parsing the caller’s arguments, and the runtime no longer depends on distutils or Python 2.7. Literal-path and failure-propagation tests pass.

## #5 — Algorithm Description

[GitHub issue](https://github.com/denglab/SeqSero2/issues/5) · Recommended status: **Close after documentation is published**

> The v1.4.0 README now explains the workflows: allele mode maps reads, microassembles determinants and scores BLAST alignments; raw-read and assembly k-mer modes compare reference 27-mers directly. It also documents subspecies identification and the forward-read sampling policy.

## #6 — Documentation doesn't give version numbers for dependencies

[GitHub issue](https://github.com/denglab/SeqSero2/issues/6) · Recommended status: **Keep closed**

> The v1.4.0 README provides workflow-specific dependency requirements and distinguishes minimum requirements from versions actually tested. Local validation used Python 3.12.16, Biopython 1.88 and native ARM64 tools. Bedtools is no longer called by the current pipeline.

## #7 — USAGE in README does not reflect default mode in v1.0.0 release

[GitHub issue](https://github.com/denglab/SeqSero2/issues/7) · Recommended status: **Keep closed**

> The current code and the prepared v1.4.0 README/help agree that allele microassembly (`-m a`) is the default. A regression check verifies the parser default. The historical v1.0.0 discrepancy does not require another algorithm change.

## #8 — BUG: ln: failed to create symbolic link (if folder exists)

[GitHub issue](https://github.com/denglab/SeqSero2/issues/8) · Recommended status: **Keep closed**

> The prepared v1.4.0 patch requires a new output directory and rejects an existing `-d` before creating links or cleaning files, including with `-c`. Tests verify that existing results remain unchanged. Please choose a new directory for each run.

## #9 — Add --check option to ensure all dependencies are installed

[GitHub issue](https://github.com/denglab/SeqSero2/issues/9) · Recommended status: **Keep closed**

> The prepared v1.4.0 `--check` returns a nonzero status when an executable is missing and includes makeblastdb and seqtk. Unused bedtools is removed from the check. It checks the union of workflows, so some listed tools remain optional for a particular input/mode.

## #10 — UnboundLocalError: local variable 'O_choice' referenced before assignment

[GitHub issue](https://github.com/denglab/SeqSero2/issues/10) · Recommended status: **Keep closed**

> The historical O_choice assignment is already corrected. The v1.4.0 preparation additionally hardens cleanup so it only removes a newly created run directory. Both regression and real installed-package clean-mode assembly checks pass.

## #11 — Is "SalmID" needed for all modes?

[GitHub issue](https://github.com/denglab/SeqSero2/issues/11) · Recommended status: **Keep closed**

> SalmID.py is needed for allele-mode subspecies identification. Assembly k-mer mode uses bundled marker sets and does not invoke it. An installed assembly run succeeds with no external executables on PATH; the v1.4.0 README now documents this distinction.

## #12 — Inconsistent naming in output files

[GitHub issue](https://github.com/denglab/SeqSero2/issues/12) · Recommended status: **Keep closed**

> Current runs use the consistent names SeqSero_log.txt, SeqSero_result.txt and SeqSero_result.tsv. These names were verified in the installed-package checks. The historical lowercase-s result filename is not generated by the reviewed version.

## #13 — judge_subspecies split error

[GitHub issue](https://github.com/denglab/SeqSero2/issues/13) · Recommended status: **Keep closed**

> The prepared v1.4.0 changes use a checked, literal SalmID invocation and reject empty, malformed or nonnumeric result tables with a clear error. They also remove the shared version.py runtime import. Tests cover invalid outputs and genuine SalmID 0.1.23 runs.

## #14 — tiny bug: output of k-mer mode only lists first of R1 and R2 files as input files

[GitHub issue](https://github.com/denglab/SeqSero2/issues/14) · Recommended status: **Keep closed**

> The prepared v1.4.0 report lists both submitted mate paths as input provenance. Raw-read k-mer mode still samples forward-read sequence for speed; listing both inputs does not mean both mates were sampled. This distinction is documented and checked with real paired reads.

## #15 — O:9 interpretation

[GitHub issue](https://github.com/denglab/SeqSero2/issues/15) · Recommended status: **Keep closed**

> The current caller already falls back to O9 when wbaV is detected without either O9,46 wzy marker. Replaying both supplied score examples returns O9. The original raw reads were unavailable, so the reason for their marker coverage was not established.

## #16 — Biopython and its version not listed in dependencies

## #21 — BWA actions in SeqSero2_package.py reference incorrect path

## #22 — Paths to source files removed from arguments to BWA commands

## #37 — Subspecies determination

No mixed-subspecies classifier or revised interpretation of SRR3418287 was validated, so the remaining question stays open.

## #39 — question "assembly track"

[GitHub issue](https://github.com/denglab/SeqSero2/issues/39) · Recommended status: **Close after documentation is published**

> Assembly k-mer mode compares reference 27-mers directly with assembly sequence; it does not run microassembly or BLAST. The README now explains this. A localization-plus-BLAST workflow would require a separate accuracy/runtime evaluation and is not implemented in this release preparation.

## #40 — Summarize SeqSero Results
